# Design direction — Character-first Purple Signal

## Source of identity

The canonical visual reference is the **original character used as the current GitHub avatar**.

The website should feel like the same person/creator as the GitHub profile, not like a separate sci-fi brand.

## Correction from the first concept

The earlier concept turned `orbit ring / depth planes / particles / Purple Signal` into a literal planet/space visual. That interpretation came from the previous product notes, not from the character itself.

That was too literal. **Space is not the brand motif.**

Orbit/particle treatments are no longer primary components. At most, a very subtle circular/signal gesture can survive where it feels like a graphic mark rather than a planet.

## Character rules

Respect:

- canonical face/silhouette from the GitHub avatar
- purple eyes
- monochrome / light neutral base with violet accents
- relaxed, slightly rough, doodle-like feeling
- “相棒と開発中”のような親しみやすい creator energy

Do not:

- redraw the character into an unrelated anime/cyberpunk person
- add arbitrary hair ornaments or costume details
- replace the character with a planet, astronaut, robot, abstract orb, or generic AI mascot
- generate a new canonical character without using an approved source image

## Visual vocabulary

Primary:

- avatar / character crop
- rough marker lines and underlines
- cursor / selection / code-edit marks
- offset frames and print-like misregistration
- dark editorial planes
- sparse violet/cyan/pink signals
- code/workbench fragments
- large Japanese/English editorial typography

Secondary:

- depth planes
- z-axis transitions
- project windows moving through depth
- soft glow only near focal elements

Avoid:

- galaxy backdrops
- star fields
- planets
- big orbit systems
- excessive neon fog
- glassmorphism dashboard grids

## Home scene translation

1. **Hero — Character / Workbench Depth**: canonical avatar is the visual anchor; creator-desk annotations move around it.
2. **Works — Project Corridor**: project surfaces move through z-space without a cosmic tunnel treatment.
3. **About — Identity Layers**: Web / AI / Community / Ops planes.
4. **Writing — Paper / Editor Stack**: notes and editor-tab behavior.
5. **Schedule — Signal Timeline**: thin line, markers and dates.
6. **Contact — Creator Finale**: visual noise reduces into a normal accessible contact form.

## Motion rules

- Scroll movement should feel dimensional, not cinematic for its own sake.
- Never hide primary text behind the character or animation.
- No loader before content.
- Reduced Motion becomes a normal editorial page.
- Mobile keeps the character but removes heavy z choreography.
