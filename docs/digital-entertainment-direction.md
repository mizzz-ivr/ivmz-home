# Digital × Entertainment — ivmz-home デザイン刷新ブリーフ

関連: Epic #99 / Issue #101（基準）・#102（Hero）・#103（3Dマスコット）・#104（ベクター）・#105（独自体験）・#106（品質）・#107（下層展開）。既存の [Character-first Purple Signal](./design-direction.md) を**置換しない補足指針**。

## 何を目指すか

**技術をつくり、公開し、育てる人の「遊べるワークベンチ」。**

最初の3秒で「何のサイトか」が分かり、作品に進むほど、キャラ・アニメ・グラフィックに世界が広がることを目指す。一般的なSaaSダッシュボードでも、企業サイトのクローンでも、重いVTuberランディングページでもない。

- **Digital（信頼・構造）:** 大きく整理された見出し、余白、読みやすい和文、技術資料やエディタの文脈、制作の裏側が分かる表現。
- **Entertainment（楽しさ・発見）:** オリジナルキャラ、ステッカー、マーカー、手描き線、リズムのある色使い、触れると反応するグラフィック。
- **交点:** 作品は「展示ブース」、スキルは「開発デスク」、Contactは「安心して話せる受付」。見栄えより情報伝達を優先する。

参考として挙がった LYCORP / DeNA / MIXI / バーチャルエンターテイメント / にじさんじ / ASOBISYSTEM から借りるのは**情報設計・空気感・体験原則**だけ。ロゴ・写真・キャラ・装飾・アニメの模倣や無断転載は行わない。参照サイトのデザインは変わり得るため、個別の画面を仕様上の絶対条件にはしない。

## 既存ブランドとの一貫性

1. 正規キャラクターは GitHub アバターのオリジナル。**紫色の目、明るいニュートラル基調**を維持。未承認の髪型・顔・衣装・アニメIPに差し替えない。
2. 現行CSSカラートークン `--color-primary` / `--color-cyan` / `--color-pink` / `--color-pop` を使い、**新しい色定数を大量に増やさない**。
3. 宇宙・惑星・銀河・安易なネオン・全面ガラスUIへ戻さない。編集痕・シール・ウィンドウ・角括弧・レイヤーで奥行きを出す。
4. 装飾の密度は Hero=高 / Works・About=中 / Contact・Blog本文=低。CTAとフォーム、読書領域を常に先に置く。
5. Dark/Light双方で成立させ、彩度・蛍光色はアクセント面積に限定する。

## Visual language

| 軸 | 推奨 | 避ける |
|---|---|---|
| タイポ | 大見出し + 可読性の高い和文 + ラベルのモノスペース | すべてを英文の小ラベルにする |
| 色 | 紫を軸にシアン / ピンク / 黄で部分的に遊ぶ | 全画面の高彩度グラデーション |
| レイアウト | Editorial grid + あえてずらしたステッカー/注釈 | 規則性のないランダム配置 |
| ベクター | オリジナルSVGの線/矩形/吹き出し/カーソル | ライセンス不明のWeb画像 |
| Motion | 操作と文脈に連動し、意味のある状態変化 | 常時回り続ける大規模な背景 |
| 3D | GLBメッシュ + idle/walk/runが分かる相棒 | 平面画像がスライドするだけの「3D」 |

## 最初の実装試作（本PR）

Heroのアバター周囲に「デジタル編集画面の注釈 × ポップなシール」を掛け合わせた、小さな**ベクターシグナル**を置く。SSR / decorative `aria-hidden` / `pointer-events:none`。デザインコアを崩さずファーストビューにわずかな楽しさを追加する。これだけでHero刷新や3D完成とは扱わない。

## 3Dキャラは別工程で実3Dを検収

- **先決:** オリジナルアバターを基にした正面・側面・背面資料、比率・服・表情、権利関係の確認。モデル素材がない場合は3D完了としない。
- **アセット:** glTF 2.0 / GLB。独立クリップ `idle` / `walk` / `run` を最低限含む。必要に応じて `turn`。スケルトン・テクスチャ・透明背景・足元位置を確認。
- **状態:** マウスとの距離/目標速度/追いついたかでidle→walk→run→idle。フレームごとにReact stateを更新しない。足の運動と速度が目視で合うようアニメを遷移させる。
- **表示:** 既存 #73 / PR #78 の2Dペットと共存させない。実モデル導入時に旧描画を置換。設定スイッチの継承は互換性を設計後に決める。
- **技術:** Three.js / R3F / dreiは候補。採用前にモジュールサイズ・GLB再生・WebGL不可・contextlost・回復・ページ遷移・省電力をSpikeで比較。現時点では依存もダミーGLBも追加しない。
- **Fallback:** 動き軽減/タッチ/非対応GPU/Canvas unavailableで静止画または非表示。必須テキストとCTAはSSR DOMに独立。
- **性能:** モデル容量、FPS、JS増分、LCP/INP/CLSはベースライン計測で具体的な上限を合意する。理想値だけで受入れにしない。

## テスト対象

- キーボード操作、ポインタがなくてもナビ・Works・Contactが使用できる
- `prefers-reduced-motion: reduce` と非対応ブラウザでも重要情報を隠さない
- 320/375/390/768/1440px、Light/Dark、ブラウザズームで装飾の重なりなし
- 3D導入時にGPU停止/タブ切替/高速カーソル/大量リサイズを追加
- ビルド/型/SSR/SEO/CSP/CI/Netlify Preview回帰を確認
- コンテンツ・セキュリティ・CMSの無関係変更は含めず、Productionは承認が出るまで操作しない
