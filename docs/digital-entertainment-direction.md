# Digital × Entertainment — ivmz design direction

> Status: Proposal / Phase 1. 承認前・Production未反映。関連 Epic #100 / #108 / #109 / #110 / #111。

## 目的とブランドの約束

「作れること」を整然と伝えながら、「つくることの楽しさ」が伝わるポートフォリオにする。最初の視線でデジタル/技術、次の視線でキャラクター/遊び、その次で制作物と信頼性を見せる。

**主題：Creator's Signal Playground（制作者の作業場に遊びが混ざる）**

- **Digital / 信頼**：明確な情報階層、技術の図像・編集記号、正確なデータ・状態、読みやすい説明。
- **Entertainment / 高揚**：オリジナルキャラ、印刷ずれ風の重なり、リズムのある色面、遊びのあるベクター、触ると小さく反応する演出。
- **Individual / 独自性**：既存GitHubアバターを主役とする。テンプレート的なネオンとガラスカードの羅列ではなく、作業ログ・選択範囲・手書きマーカー・制作チケットをブランド語彙にする。

LINEヤフー・DeNA・MIXIからは情報設計・企業サイトの信頼感、バーチャルエンタメ・にじさんじ・ASOBISYSTEMからはキャラクター性・楽しさ・大きなタイポと編集的な画面展開の考え方を参照する。**特定サイトの画面をコピーせず、素材・イラスト・商標を借用しない**。

## 既存方針との関係

`docs/design-direction.md`の「Character-first Purple Signal」を発展させる。旧稿の注意事項（惑星・銀河・宇宙感、過剰なneon、glassmorphismの汎用UI、情報を隠すアニメーションの禁止）は引き続き有効。

現状のHeroで使われる`orbit-ring`/回転するsatellitesは惑星風に見えやすいため、Phase 1では**作業中のインク線・編集記号を使ったオリジナルSVG**へ置換する。キャラの出典画像、見出し、作品/Contactリンクは維持し、イベント/データ処理には触れない。

## ビジュアルの文法（実装可能な粒度）

| 軸 | 方針 | 避けるもの |
| --- | --- | --- |
| 色 | Violetを主軸に、cyan/pink/yellowは場面ごとに役割を決めて強調。ライト・ダーク両対応 | 全カードが蛍光色、意味のない発光 |
| 文字 | 大きな日本語見出し、短い英字ラベル、Monoは技術/状態に限定 | 等級のない巨大文字の乱用 |
| 形 | オフセットフレーム、少し不規則な角、線・タブ・チケット片 | すべて同じ角丸カード |
| 図像 | 軌跡線、切り抜き紙片、選択範囲、マーカー、プロセス線画 | 惑星・銀河・generic AI robot |
| 動き | カーソルへの小さな追従、スクロール時の編集的遷移、停止条件がある軽いアニメ | コンテンツを待たせるローダー、揺れ続ける全文字 |
| 写真/絵 | オリジナルアバター中心、出典を管理したSVG/3D | 他社IP・無断転載したキャラの流用 |

## 画面別の役割

- **Hero**：大きな人物/キャラ、言葉、オリジナルの「制作中の信号」SVGを1つのシーンに。Works/ContactへのCTAは最優先。
- **Works**：技術と成果がわかるカードに、使うほど「制作過程」が見える小さなインタラクション。
- **About**：作業机/編集タブ/工程図のレイヤー。実務経験や範囲を本文で説明。
- **Blog / News**：記事自体の読みやすさを優先し、エディトリアルな区切りと軽いイラストのみ。
- **Schedule**：実際の日付・イベントが最優先。タイムラインを線のモチーフとして利用。
- **Contact**：視覚ノイズを減らす。入力・送信・失敗時の理解を最優先、Decorは入力欄に重ねない。

## 3Dキャラクターの責務と前提

**PR #78は2Dの仮体験**であり「完成した3D追従」と扱わない。#110で本物の軽量rigged GLB、Idle/Walk/Run/Turn/Stopのクリップ、向き・移動速度の状態遷移、性能計測、ユーザー設定を別PRで実装する。

オリジナルアバターの容姿を損なわず、**モデル制作元・著作権・公開範囲・ライセンスが確認されたモデル**に限る。素材が決まるまでは旧2D演出を保持するか静止化し、別の3Dモデルを「完成」と称しない。Next.js SSR/メインコンテンツの表示に3Dを依存させない。

## Phase 1のスコープ

1. デザイン言語を文書化
2. 既存Heroの`orbit`を独自SVGの「Signal Trace」に置換（Planetでなく、制作軌跡/線画）。レイアウトや文言・APIは変えない
3. モーションは装飾のみ、reduced-motionでは完全静止。スマホでは描画を抑え、CTAの可読性を保証
4. CI/Previewで差分検証を行い、次のHero全体刷新で採用可否を判断

## 受け入れ・レビュー

- 静的描画時もSVGが見え、失敗時でも既存アバター・見出し・CTAが残る
- SVGは装飾なので`aria-hidden`、`focusable=false`、ポインターイベントなし、外部通信/スクリプトなし
- 320/375/390px、1440px、ライト/ダーク、reduced-motion、印刷で破綻しない
- Layout Shiftなし、余計なJSバンドルや外部画像の増加なし
- E2Eで作品/Contact導線、Hero見出し、画像が保持される
- **Phase 1はデザイン土台の提案であり、3Dマスコット本体の完成ではない**。#110の実装をもって別途レビューする

## 実装・権限のルール

- CSS/HTML/SVGを軸に必要最小限で変更し、既存CMS/認証/問い合わせ処理へ影響させない
- 独立したDraft PRでCI・Netlify Previewを検証、承認前はmainマージしない
- 新規素材は作者、採用理由、ライセンス、ファイルサイズを記録し、第三者IPと混同しない
