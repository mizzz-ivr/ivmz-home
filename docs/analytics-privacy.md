# GA4 アクセス解析（オプトイン）

## 目的
個人サイトの閲覧数・ページ別の利用傾向を把握する。業務問い合わせ、CMS、匿名メッセージ、AI質問文は収集対象外。

## 導入
1. Google Analytics 4でWebデータストリームを作り `G-...` の測定IDを取得する。
2. Netlify環境変数 `NEXT_PUBLIC_GA_MEASUREMENT_ID` をProductionで設定し、Git連携から再デプロイする。測定IDは公開値でありAPIキーではない。
3. 公開画面で同意パネルが表示されることを確認。**同意前にはGoogle Analytics / Google Tag Managerへ通信しない**。
4. 同意後にDebugViewやNetworkタブで `page_view` を確認。拒否/撤回時にはタグがロードされないことを確認。
5. Previewでは原則測定IDを設定せず、Productionの数値へ混入させない。

## プライバシーとアクセス
- Basic Consent Mode: 初回はGoogleスクリプトを一切読み込まない。拒否時も読み込まない。
- 同意は端末内のLocalStorageに記録。フッターの「アクセス解析の設定」で再表示、拒否へ変更できる。
- 同意後に拒否へ変更した場合はリロードし、既に読み込んだタグを終了する。過去に送信された統計は取り消せない。
- GA4が作ったCookieの自動削除、Google側のデータ削除設定、外部送信先の法令確認は別途運用で実施する。
- 管理画面、API、問い合わせ、匿名メッセージ、法律ページは追跡しない。クエリ文字列は送らない。
- 利用者ID、氏名、メール、問い合わせ本文、AIチャット内容をイベントプロパティに含めない。
- CSPはReport-OnlyのGoogle配信/計測ドメインだけを許可。無制限のscript-srcを設定しない。

## 未設定・障害時
- 測定IDが空/不正なら同意UIもタグも表示しない。サイト表示には影響させない。
- Google側障害・広告ブロックでも、通常ページ・Contact・CMSは使える。
- Payload CMS内のGA4集計表示は Issue #75 で別管理し、Data API読み取り用のバックエンド権限とコスト管理を決める。
